# MHINet-v2 Stage1 三阶段渐进式注意力改造：完整实验计划

实验方案 V1.0｜2026-11-07｜仅改造 Stage1，不修改 CGMDP、D8、D2、QRRU

## 一、研究目标与最终模型

本轮实验的目的不是让 Stage1 单纯变得更复杂，而是验证一个具体假设：

将原 MVT 的一次性全局特征交互，改为三阶段预测、两阶段 Flow–Matchability 引导的跨图特征更新，是否能让最终 Flow 更准确，并提高后续 D8/D2 的匹配精度？

按照我们已经确定的方案，最终模型结构固定为：

DINOv3 ViT-L/16（冻结）

L11 / L17 → 2048→768

[B, 2, 1024, 768]

Stage I｜MVT Blocks 1–4

原始 Joint / Single Attention 交替

Head 1 → Flow¹、Mat¹、P¹

Stage II｜MVT Blocks 5–8

Blocks 5、7：逐 Query Guided Cross-Attention

Blocks 6、8：原始 Single Self-Attention

局部自适应 5×5 + Top-3 峰各 3×3

Head 2 → Flow²、Mat²、P²

Stage III｜MVT Blocks 9–12

Blocks 9、11：逐 Query Guided Cross-Attention

Blocks 10、12：原始 Single Self-Attention

根据 Flow²、Mat²、P² 更新采样及注意力

Head 3 → 最终 Flow³、Mat³、P³

\\(F\_{\mathrm{MVT}}\\)

32×32×1024

→ CGMDP

Flow³ / Mat³

D16 全局先验

→ D8

## 二、整个实验分为五个阶段

1. P0：基线冻结与模型接口验证

   固定数据、代码、权重和评价协议，保证后续结果可严格比较。
2. P1：三阶段 Head 深监督实验

   保留原 12 Block 注意力，只增加第 4、8 层的中间预测，验证多轮预测是否具有价值。
3. P2：逐 Query Flow 引导注意力实验

   依次加入固定局部、自适应局部、多峰候选和 Matchability 加权，找出真正有效的部分。
4. P3：完整 Stage1 训练与消融

   对有效结构进行统一训练，验证不同阶段的 Flow 变化、跨域泛化和稳定性。
5. P4：衔接 D8/D2/QRRU 验证

   先冻结原有下游测试，再用相同训练预算适配下游，验证最终匹配收益。

## 四、P1：三阶段 Flow Head 深监督

这一阶段不引入新 Guided Attention，先回答一个基础问题：

原本需要 12 层 MVT 才能完成的 Flow 定位，如果在第 4、8 层也加入监督，能否促使中间特征提前形成可靠对应关系？

### 4.1 B0：原始模型基线

结构：

\\[ DINO\rightarrow MVT\_{12}\rightarrow Head \\]

保持旧结构、旧定位方式。

记录：

\\[ EPE^0,\quad FlowP\@3^0,\quad Mat^0 \\]

同时测量完整 Stage1 与冻结下游的表现。

为公平比较，保留两种 B0 结果：原始发布 checkpoint 的零训练结果，以及使用与新模型相同优化步数、相同解冻策略继续训练的 B0-finetune。后者才作为主要训练对照。

### 4.2 B1：三阶段 Head，但不反馈注意力

结构：

\\[ X^4\rightarrow Head_1 \\]

\\[ X^8\rightarrow Head_2 \\]

\\[ X^{12}\rightarrow Head_3 \\]

全部 12 个 Block 仍为原始 MVT。

三个阶段分别监督：

\\[ \mathcal L= 0.2\mathcal L_1+ 0.3\mathcal L_2+ 0.5\mathcal L_3 \\]

其中每个 \\(\mathcal L_t\\) 都包含 Flow 几何损失、Matchability 损失和对应分类损失，初始沿用当前 Stage1 的损失定义与内部系数。

### 4.3 预测头的组织

首轮固定以下结构：

- 第 4、8 层增加独立的 LayerNorm；
- 原 MVT 的 768→1024 输出投影尽量共享；
- MatchEmbeddingDecoder 及其 No-match 参数共享；
- 第 12 层保持原有输出计算路径；
- 三个阶段分别计算新的匹配概率分布。

这种实现使得结构差异主要来自中间监督，而不是新建三套完全独立的定位网络。

### 4.4 B1 需要重点记录什么？

阶段性 Flow 结果

| 指标                   | Head 1（Block 4） | Head 2（Block 8） | Head 3（Block 12） |
| -------------------- | --------------- | --------------- | ---------------- |
| EPE ↓                | 记录              | 记录              | 记录               |
| Flow-P\@3 ↑          | 记录              | 记录              | 记录               |
| Flow-P\@10 ↑         | 记录              | 记录              | 记录               |
| Matchability AUROC ↑ | 记录              | 记录              | 记录               |
| 高置信大误差比例 ↓           | 记录              | 记录              | 记录               |
| No-match Recall ↑    | 记录              | 记录              | 记录               |

不要假设 Head 1 → 2 → 3 一定单调改善；应统计每对影像、每个有效 Query 的变化。

### 4.5 B1 之后的判断

如果 Head 1 已有相当比例的正确候选，P2 可以正常开始。

如果 Head 1 的单点 Flow-P\@3 较低，也不应立即否定。因为你后续使用的是局部 + 多峰候选集合，而不是只使用单点 Flow。

更重要的是 Head 1 的真实对应位置是否能被候选集合接近或覆盖。

这项检查在 B1 训练过程中同步完成，不单独设立一个必须提前通过的验证阶段。

## 五、P2：Guided Attention 的核心实验

这一阶段以完成训练的 B1 为起点，替换原 MVT 的 Blocks 5、7、9、11。

所有 G1–G5 实验保持以下部分一致：

- 12 Block 总深度；
- Head 1/2/3 的预测结构；
- 主特征 768 维；
- Guided QKV 256 维；
- 8 Heads；
- 双向 Cross-Attention；
- Blocks 6、8、10、12 的单图 Attention；
- 数据、优化步数、学习率计划和验证协议。

这样尽可能只改变关注的 Attention 机制。

### 5.1 G1：固定 5×5 局部采样

第一个实验暂时不加入多峰，也不使用 Matchability 权重。

每个 Query 根据前一阶段 Flow 坐标 \\(\mu_i\\)，在 B 中构造一个固定采样网格：

\\[ \Gamma_i=\\{\mu_i+(a,b)\Delta\\} \\]

其中：

\\[ a,b\in\\{-2,-1,0,1,2\\} \\]

初始：

\\[ \Delta=1 \\]

单位是 D16 网格像素。

因此每个 Query 采样 25 个 K/V。

注意力：

\\[ M_i=\operatorname{Attention}(Q_i,K\_{\Gamma_i},V\_{\Gamma_i}) \\]

目的：先验证使用 Flow 引导跨图特征更新，是否比 B1 只有中间监督更有效。

但 G1 同时将原 Joint-Attention 替换成了低维 Cross-Attention。为了严谨，建议增加一个小型控制实验 G0：使用同样 256 维的新 Cross-Attention，但不使用 Flow 空间限制。这样可以区分“更换注意力类型”和“引入几何采样”的贡献。G0 仅作控制，不属于最终模型的全局回退设计。

### 5.2 G2：自适应局部 5×5

保持 25 个采样点不变，改为根据现有 \\(P_i\\) 估计两个方向的采样间距：

\\[ \Delta\_{x,i}= \operatorname{clip} (c\sigma\_{x,i},0.5,3.0) \\]

\\[ \Delta\_{y,i}= \operatorname{clip} (c\sigma\_{y,i},0.5,3.0) \\]

其中 \\(\sigma\_{x,i},\sigma\_{y,i}\\) 由 Flow 中心附近的概率分布计算，而不是新预测的标准差。

候选为：

\\[ \Gamma_i= \left\\{ \mu_i+ (a\Delta\_{x,i},b\Delta\_{y,i}) \right\\} \\]

推荐首轮对系数 \\(c\\) 做有限网格：

\\[ c\in\\{0.5,1.0,1.5\\} \\]

根据验证集选择一项后冻结，避免每个实验使用不同的搜索范围规则。

特别注意，当局部概率质量接近零时，采用预设最大间距，避免数值不稳定。

G1 vs G2 主要验证动态跨度是否比固定跨度有效。

### 5.3 G3：自适应局部 + Top-3 多峰

保持 G2，新增最多三个独立的空间概率峰。

通过空间 NMS 从 \\(P_i\\) 中提取：

\\[ \\{c_i^1,c_i^2,c_i^3\\} \\]

每个峰附近采样 3×3：

\\[ \Gamma_i^{peak}= \bigcup\_{k=1}^{3} \left\\{c_i^k+(a,b)\right\\} \\]

其中 \\(a,b\in\\{-1,0,1\\}\\)。

最终：

\\[ \Gamma_i= \Gamma_i^{local}\cup\Gamma_i^{peak} \\]

每个 Query 最多 52 个候选。

实现时必须区分三种情况：

| 情况         | 处理                |
| ---------- | ----------------- |
| 存在三个有效独立峰  | 使用完整 52 个候选       |
| 不足三个峰      | 使用实际峰数，其他位置 Mask  |
| 局部采样与某个峰重合 | 去重或屏蔽重复点，保留候选预算上限 |

NMS 只对 1024 个空间候选进行，不把 No-match 当作峰值。

G2 vs G3 验证多峰机制是否为正确对应提供额外的候选覆盖，而不是仅仅使搜索范围变大。

### 5.4 G4：增加 Matchability Key Bias

保持 G3 的候选集合，只在注意力得分中加入目标图像侧 Matchability：

\\[ \boxed{ L\_{ij} = \frac{Q_iK_j^\top}{\sqrt d} +\alpha\log(\tilde m_B(q\_{ij})) } \\]

其中：

\\[ \tilde m_B=m\_{\min}+(1-m\_{\min})m_B \\]

建议初始：

\\[ m\_{\min}=0.1,\qquad \alpha=0.5 \\]

上述为起始超参数，后续根据 G4 的验证结果确定是否调整。

Key 的 Matchability 需要在目标采样位置通过双线性采样取得，和 K/V 使用相同的坐标。

此实验不改变 Query 的消息强度，仅比较目标侧加权对跨图交互的影响。

### 5.5 G5：加入 Query Gate，构成完整模型

在 G4 基础上增加 Query 侧门控：

\\[ g_i= g\_{\min}+(1-g\_{\min})m_A(i) \\]

初始：

\\[ g\_{\min}=0.2 \\]

最终特征更新：

\\[ \boxed{ X_i^{new}= X_i+ g_iW_O\left( \sum_j\operatorname{Softmax}(L\_{ij})V_j \right) } \\]

注意这个 Gate 只作用于跨图 Attention 消息，不应直接抑制后面的单图 Self-Attention 或整个主干残差。

这是当前计划中的完整模型候选。

### 5.6 G1–G5 应当怎样判断？

| 比较      | 核心问题                        |
| ------- | --------------------------- |
| B1 → G1 | Flow 引导的特征更新是否有效            |
| G1 → G2 | 动态跨度是否优于固定跨度                |
| G2 → G3 | 多峰候选是否弥补单中心错误               |
| G3 → G4 | Key Matchability 是否提高有效信息聚合 |
| G4 → G5 | Query Gate 是否进一步改善结果        |

如果某项模块没有稳定贡献，最终模型可以舍弃它。实验计划的目的不是证明所有设计都有效，而是找到可以被数据支持的有效机制。

## 六、P3：完整 Stage1 训练

P2 的目的是拆解机制，P3 则是对最终选择的结构进行完整训练。

这里不要求最终模型必须保留 G5 的全部组件，而是以验证结果最好的有效组合为准。

### 6.1 统一训练配置

建议从你现有 Flow Head 训练配置出发。仓库中的 `flow_head_rgb512_seed42.json` 使用过学习率 `1e-5`、AdamW、梯度累积 8、Warmup 250 Steps 和 5 Epoch，但那是原 Flow Head 的训练设置，不能直接认为适用于解冻后的新 MVT。

新实验建议采用：

| 参数                          | 初始方案                          |
| --------------------------- | ----------------------------- |
| 输入                          | 512×512，双图                    |
| DINOv3                      | 全程冻结                          |
| 优化器                         | AdamW                         |
| 训练 Epoch                    | 10，所有主要对照保持一致                 |
| Effective Batch             | 8，显存允许可增大，但所有对照一致             |
| 新 Guided Attention LR       | 1×10⁻⁴                        |
| 新 Head 适配层 LR               | 1×10⁻⁴                        |
| 原有 MVT LR                   | 1×10⁻⁵                        |
| 原有 MatchEmbeddingDecoder LR | 1×10⁻⁵                        |
| Weight Decay                | 1×10⁻⁴                        |
| Warmup                      | 总优化步数的前 5%，初始可与原 250 Steps 对照 |
| Scheduler                   | Warmup + Cosine               |
| 梯度裁剪                        | Global Norm 1.0               |
| 主实验 Seed                    | 42                            |
| 复现 Seed                     | 123、3407                      |

以上是待验证的实验配置，不是已经证明最优的训练参数。

对于 B0-finetune、B1 和 G1–G5，应使用相同训练数据、总优化步数及解冻预算。不同模块可采用不同学习率组，但不能给某个实验额外增加训练轮数。

正式训练不启用早停；完整执行预设训练预算，然后从固定验证集选择 checkpoint。

显存不足时，可以通过梯度累积、Activation Checkpointing 或逐 Query Chunk 处理解决，而不需要直接缩减模型结构。

### 6.2 分阶段初始化

我建议保留三种初始化策略，并先确定默认方案：

| 初始化 | 方法                                  | 建议   |
| --- | ----------------------------------- | ---- |
| I0  | 原预训练 MVT + 原 Flow Head，新增模块随机初始化    | 主方案  |
| I1  | I0 + 新 Guided Block 从原 QKV 参数做低秩初始化 | 后续消融 |
| I2  | 全部 MVT 和 Head 从头训练，DINO 冻结          | 不优先  |

I0 最容易确定新增注意力机制的贡献。

对于 Guided Attention 的输出投影，可以使用零初始化或很小的残差缩放系数，使新模块开始训练时不会立即产生过强的跨图更新。

不过，由于它已经替换了原 Block 的 Joint-Attention，零初始化只能减轻扰动，不能保证新旧 Block 初始输出完全相同。所以必须记录替换前后的特征变化。

### 6.3 每轮深监督损失

继续使用：

\\[ \boxed{ \mathcal L= \sum\_{t=1}^{3}\lambda_t \left( \mathcal L\_{\mathrm{geo}}^t+ \alpha\mathcal L\_{\mathrm{mat}}^t+ \beta\mathcal L\_{\mathrm{cls}}^t \right) } \\]

首轮：

\\[ (\lambda_1,\lambda_2,\lambda_3) =(0.2,0.3,0.5) \\]

三个阶段都监督：

- Flow 对应坐标；
- Matchability；
- 全局位置概率分布及 No-match。

保持当前代码中精确几何、近似 H 和稀疏点监督的不同处理方式，不将杭州近似 H 强行转成逐点精确标签。

这里有一个重点：Matchability 不参与几何损失的预测权重。即使模型预测某位置 Matchability 很低，只要 GT 证明存在有效对应，仍应进行几何监督。

### 6.4 梯度路径实验

默认采用较保守的梯度路线：

```
# 第 t 阶段预测flow, mat, probability = head(feature)# 空间采样先不向预测坐标回传匹配梯度grid = build_grid(    flow.detach(),    probability.detach())# 第一版也先切断通过匹配性门控的反向梯度message = guided_attention(    feature_a,    feature_b,    grid,    mat.detach())# 更新特征，进入下一阶段feature_next = update(feature, message)
```

这样当前 Head 有明确的深监督来源，而后续任务通过视觉特征更新路径反向传播。

在 G5 有效之后，再增加两组消融：

| 实验   | 修改                            |
| ---- | ----------------------------- |
| A3-1 | 开放连续 Flow 采样坐标的梯度             |
| A3-2 | 开放 Matchability Bias/Gate 的梯度 |

Top-K 与 NMS 的离散选峰索引仍不直接求导。

这样可以判断，像 ASpanFormer 那样 Detach 采样位置是否更稳定，还是让下游匹配损失直接优化连续采样位置更好。

## 七、每次训练必须保存的逐层诊断

这一部分建议作为正式实验代码的一部分，不要只在训练结束后手动写分析脚本。

### 7.1 三阶段预测精度

| 指标                        | Stage I | Stage II | Stage III |
| ------------------------- | ------- | -------- | --------- |
| Flow EPE                  | 记录      | 记录       | 记录        |
| Flow-P\@1                 | 记录      | 记录       | 记录        |
| Flow-P\@3                 | 记录      | 记录       | 记录        |
| Flow-P\@5/10              | 记录      | 记录       | 记录        |
| Matchability AUROC        | 记录      | 记录       | 记录        |
| No-match Precision/Recall | 记录      | 记录       | 记录        |

除三个阶段的平均指标，还需要逐 Query 统计：

\\[ \Delta EPE\_{1\rightarrow2} =EPE^1-EPE^2 \\]

\\[ \Delta EPE\_{2\rightarrow3} =EPE^2-EPE^3 \\]

统计被纠正和变差的 Query 比例。

尤其要区分：

- 原本正确，下一阶段仍然正确；
- 原本错误，下一阶段纠正；
- 原本正确，下一阶段反而变错；
- 三个阶段始终错误。

这样可以直接判断三阶段更新有没有形成稳定的改善。

### 7.2 局部与多峰的候选贡献

这是验证 G3 的关键。

对于具有精确 GT 的 Query，定义：

\\[ d_i^{local} = \min\_{q\in\Gamma_i^{local}} \\|q-q_i^{gt}\\|\_2 \\]

\\[ d_i^{peak} = \min\_{q\in\Gamma_i^{peak}} \\|q-q_i^{gt}\\|\_2 \\]

\\[ d_i^{all} = \min(d_i^{local},d_i^{peak}) \\]

全部转为原始输入图像的像素单位。

建议记录：

| 指标                 | 含义                           |
| ------------------ | ---------------------------- |
| Local-Coverage     | GT 位于局部采样窗口内的比例              |
| Local-Near\@3/8/16 | 最近局部采样点距 GT 不超过 3/8/16 px    |
| Peak-Near\@3/8/16  | 多峰采样最近距离                     |
| Union-Near\@3/8/16 | 合并候选后的最近距离                   |
| Peak-Rescue\@8     | 局部未覆盖、但多峰候选在 8 px 内找到 GT 的比例 |
| Peak-Duplicate     | 多峰候选与局部候选的重复率                |

这里必须同时记录“搜索区域覆盖”和“最近离散采样点距离”。

因为 D16 一个网格像素对应原图 16 px，即使 GT 在窗口内部，也不代表离散采样点能在原图 3 px 内接近 GT。

不建议用单独一个 Coverage\@3 代替所有诊断。

### 7.3 Matchability 对 Attention 的真实影响

在 G4 和 G5 中记录：

\\[ \bar m_A,\quad \bar m_B \\]

以及每个 Query 的跨图消息变化：

\\[ R_i= \frac{\\|g_iM_i\\|\_2} {\\|X_i\\|\_2+\epsilon} \\]

观察低 Matchability 区域是否被合理抑制，以及高 Matchability 区域是否获得更强的跨图信息。

另外单独统计高置信大误差：

\\[ R\_{\mathrm{HE}}= P(EPE>10\text{ px}\mid m>0.7) \\]

这里的 10 px 和 0.7 是建议固定的诊断阈值，不是要在训练中使用的裁剪条件。

因为你之前的杭州 G3 已经出现过高 Matchability 但整体错位的情况，这项指标应作为必报结果。

### 7.4 可视化输出

每组实验至少选取固定的典型影像对，保存三轮结果：

- 三阶段 Flow 位移图、GT 和残差图；
- 三阶段 Matchability 热图；
- 每个阶段选定 Query 的局部和多峰采样位置；
- 不同阶段同一个 Query 的 Attention 权重；
- 正确匹配被多峰挽救、未被挽救的典型案例；
- 杭州 G0–G3 的代表性成功与失败案例。

这些图既用于诊断，也能直接成为论文消融与机制可视化的素材。

## 八、P4：与 D8/D2/QRRU 的衔接验证

Stage1 的最终目标不是 EPE 最低，而是让下游的匹配效果更好。因此 P4 必须单独安排。

### 8.1 D1：冻结下游，直接替换 Stage1

固定当前已训练的：

\\[ CGMDP\rightarrow D8\rightarrow D2\rightarrow QRRU \\]

仅替换：

\\[ (F\_{\mathrm{MVT}},Flow0,Mat0) \\]

为新 Stage1 的最终输出。

这一步验证新 Stage1 是否具有直接兼容性。

由于 MVT 的特征分布可能发生变化，D1 即使下降，也不能直接证明新架构无效；但必须报告下降幅度，不能跳过。

### 8.2 D2：相同预算重新适配下游

对 B0-finetune 和最终新 Stage1 分别执行相同的下游训练：

1. 固定 Stage1、训练 CGMDP/D8/D2；
2. 保持相同的数据、训练轮数、优化器与 checkpoint 选择规则；
3. 根据最终完整路径的验证集 P\@3 选择模型；
4. 如 QRRU 在当前正式配置中启用，使用同样的 QRRU 权重或同样预算重新适配，不允许只给新模型额外优化。

特别注意两种对比不能混淆：

| 比较                        | 证明什么       |
| ------------------------- | ---------- |
| B0 原下游 vs 新 Stage1 + 冻结下游 | 直接替换的兼容性   |
| B0 重新适配 vs 新 Stage1 重新适配  | 新架构的完整训练收益 |

第二个才是判断最终模型是否优于原 Stage1 的核心实验。

## 九、消融实验怎么取舍？

核心 G1–G5 跑完后，我建议只围绕三个真正可能影响创新结论的因素展开。

### 9.1 多峰数量与采样预算

| 实验 | 局部候选 | 多峰候选  |
| -- | ---- | ----- |
| K0 | 25   | 0     |
| K1 | 25   | 1×3×3 |
| K2 | 25   | 2×3×3 |
| K3 | 25   | 3×3×3 |
| K4 | 25   | 4×3×3 |

K3 是当前默认。

如果 K1 与 K3 的性能接近，说明增加多个峰并没有产生足够的收益；如果 G3 特别是在 G3 地理组的大错位样本上明显优于局部方案，则能支持多峰候选的设计价值。

同时建议补充一个固定总预算对照：局部候选和多峰候选的数量之和保持相同，改变两者分配比例。否则多峰提升可能仅仅来自候选总数增加。

### 9.2 特征维度

保持最终注意力与采样策略一致：

| 实验 | QKV 维度 | Heads |
| -- | ------ | ----- |
| C0 | 128    | 4     |
| C1 | 256    | 8     |
| C2 | 384    | 12    |
| C3 | 768    | 12    |

所有维度的单 Head 特征数均为 32 或 64，确保合理整除。

这组实验需要比较 Flow-P\@3、最终 P\@3，以及模型参数量。推理耗时可以同时记录，但不作为选择的唯一标准。

256 是建议起点，不必预设最后一定选择 256。

### 9.3 三阶段设计本身

如果核心模型有效，建议补充：

| 实验 | 设计                   |
| -- | -------------------- |
| T0 | 12 Block 后只预测一次 Flow |
| T1 | 4/8/12 三次预测，不进行反馈    |
| T2 | 4/8/12 三次预测，两次反馈     |
| T3 | 6/9/12 三次预测，两次反馈     |

T3 是一个有价值的附加对照：验证收益来自三阶段反馈本身，还是依赖特定的 4+4+4 层数划分。

T3 需要修改原本的联合/单图注意力切分位置，因此应明确记录具体替换 Block，避免只比较分段标签。

## 十、结果选择与停止规则

为避免后续反复调整实验标准，建议现在就固定以下规则。

### 10.1 主指标

Stage1 独立研究：

- 主要：RGB 验证集 Flow-P\@3；
- 辅助：Flow-P\@1/5/10、EPE；
- 机制诊断：三阶段改善比例、候选覆盖、Matchability 质量。

完整模型：

- 主要：最终匹配 P\@3；
- 必报：OverlapPre\@3；
- 辅助：P\@1/5/10、RMSE、有效匹配数量和大错位失败率。

### 10.2 Checkpoint 选择

Stage1 实验统一根据 RGB 完整验证集 Flow-P\@3 选最佳 checkpoint；如出现数值接近的结果，以 EPE 作为辅助判据。

当进入 D8/D2 完整模型实验，统一改为依据 RGB 完整验证集的 Matching P\@3 选择最佳 checkpoint。

不能因为某个实验在杭州测试集表现更好，就事后更换模型选择规则。

### 10.3 推荐的通过标准

以下是建议的研究目标，而不是宣称模型一定能达到的结果。

| 判断               | 建议标准                                          |
| ---------------- | --------------------------------------------- |
| 三阶段机制有效          | G5/最佳 G 方案在独立验证集的 Flow-P\@3 优于 B1，且不是由极少数样本驱动 |
| 多峰机制有贡献          | G3 优于 G2，并能观测到独立的 Peak-Rescue 样本              |
| Matchability 有贡献 | G4/G5 在可匹配区域或 No-match 区域有稳定改善                |
| 下游收益成立           | 重新适配后的完整模型 P\@3 优于同预算原基线                      |
| 跨域结论             | 杭州 G0–G3 单独报告，不掩盖某一组的严重下降                     |
| 复现性              | 最终候选在 3 个 Seed 下报告均值、标准差和逐对差异                 |

可以将验证集 P\@3 提升至少 1 个百分点作为有实践意义的目标，但不应把它当成统计显著性的证明。建议采用按来源场景分组的配对 Bootstrap 置信区间进行补充分析。

### 10.4 何时终止某项技术路线？

不需要因为模型变慢而停止。

更合理的停止条件是：

- 出现无法解决的数值不稳定；
- G1/G2 在相同训练条件下持续明显劣于 B1；
- 多峰候选几乎没有带来独立召回，且 G3 不能优于 G2；
- Matchability 加权稳定导致有效对应区域信息被抑制；
- 完整训练及相同预算的下游适配后仍无匹配收益。

这样可以把实验集中在真正有研究价值的机制上。

## 最终研究重点

我认为本次实验应围绕三个逐步递进的研究结论展开。

第一个结论：多阶段监督是否让 MVT 的中间特征更早建立准确对应？

由 B0、B1 和三阶段 Flow 指标验证。

第二个结论：Flow 局部位置与多峰匹配假设共同引导的跨图注意力，是否优于单中心的局部搜索？

由 G1–G3 及候选独立召回验证。这是本轮最有可能形成方法贡献的部分。

第三个结论：Matchability 引导跨图信息的接收和聚合，是否可以进一步改善最终匹配？

由 G3–G5 和下游实验共同验证。

最终论文不应仅用 Flow EPE 降低支撑整个方法。最有说服力的证据应当是：三阶段更新能够逐轮纠正错误对应，多峰候选确实补充了局部搜索遗漏的位置，并且这些改善最终转化为 D8/D2 的 P\@3 提升。

因此，我建议严格按 B0 → B1 → G1/G2 → G3 → G4/G5 → 下游验证 的顺序实施；不额外把时间消耗作为技术路线的否决条件，也不提前引入新的几何模块。
