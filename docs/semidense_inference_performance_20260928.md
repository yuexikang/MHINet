# QRRU 与 D2 推理耗时分析（2026-09-28）

结论：当前主要可优化项是推理分块过小和重复调度/同步。三对真实测试影像的分块对照已经证实显著提速空间；不是完整验证，也没有修改生产推理配置或C/D/E测试结果。

## 实测：只改 window_chunk

同一第三档C权重、RTX4090 GPU0、同三对输入（测试索引0/666/1333）、每种配置单独预热后测两次，保持12000匹配点上限和4轮QRRU。顺序测试，未随机化顺序；其他GPU同时在跑测试。计时为现有CUDA事件阶段及墙钟，不是纯kernel时间。

| 分块 | 总耗时 ms | D2 ms | QRRU ms | 相对32加速 |
|---|---:|---:|---:|---:|
| 32 | 3779.86 | 771.22 | 2908.85 | 1.00× |
| 128 | 1041.04 | 200.92 | 743.90 | 3.63× |
| 256 | 562.21 | 101.53 | 365.94 | 6.72× |
| 512 | 332.28 | 51.70 | 185.77 | 11.38× |
| 1024 | 216.15 | 28.66 | 92.65 | 17.49× |

本轮各组peak_allocated约1.916 GiB；它不是进程总显存或reserved峰值，不能由此推出任意分块都不增加显存。128分块在这三对中坐标、顺序和置信度逐位一致。更大分块存在排序或浮点差异；三对precision@1px均未变化，EPE变化很小，但仍需全量精度验证。

## 原因与代码证据

1. `mhinet/downstream/semidense.py` 的 D2/QRRU 共同使用 `window_chunk=32`。训练查询上限分别为64个fine窗口/128个QRRU点，而推理实际可达6000个粗匹配和12000个细匹配点；训练用的小分块被直接用于推理。C完整测试粗匹配平均约4403，D2约需138个分块；QRRU接近12000点时375个分块，每块4轮。
2. QRRU只有96339个参数，但每轮有7个Conv2d模块调用。12000点/32/4轮意味着约10500次卷积模块调用，处理的空间仅4×4或2×2。这是模块调用计数，不能等同于CUDA kernel数量；小算子调度与CPU提交间隙需要在性能分析中考虑。
3. `mhinet/downstream/semidense.py:202` 每个QRRU块都把CUDA求和转Python int，产生等待GPU结果的同步；最多375次。应累积GPU计数后统一取回。D2中的动态nonzero/筛选也有同步与小张量开销。
4. `mhinet/pretraining/loss.py:13` 是为训练确定性反传实现的四邻点gather双线性采样。QRRU每块采A一次、每轮采B一次，按375块为1875次采样，每次包含4个邻点分支；不是单个融合采样算子。D2也使用该采样器。
5. QRRU普通推理仍计算并stack所有轮的flows/centers/grids/gates；调用方只用最后一轮centers/grids。`interpolate_controls`的固定插值权重重复创建，fine_grids也按块重复构建98×98网格和4×4偏移。
6. D2耗时主要是细匹配阶段，不等于生成D2描述子的时间。CGMDP描述子解码在此前完整C计时中约13.57ms；D2细匹配约736ms，QRRU约3049ms。

## 建议实施优先级

| 优先级 | 动作 | 约束/验收 |
|---|---|---|
| 1 | 拆出推理专用 fine_chunk / qrru_chunk，先比较128/512/1024 | 训练分块不变；先保持点数、4轮、H0残差先验；完整val比较点集合、P@1px、EPE及失败率 |
| 2 | QRRU越界计数留GPU，循环结束再取回；缓存网格和插值权重 | 结果/计数应一致，验证无边界语义变化 |
| 3 | 单独的QRRU推理返回路径只生成最后状态，诊断模式才保留轨迹 | 不改变迭代更新公式；训练和详细可视化仍保留轨迹 |
| 4 | 推理使用融合双线性采样，如grid_sample或专用实现 | zero padding、align_corners=False、半像素坐标与边界必须等价；训练确定性采样不动 |
| 5 | 在固定批形状下评估torch.compile/CUDA Graph与算子融合 | 需要处理动态筛选、尾块及编译预热；收益尚未测量 |
| 6 | 减少点数、减少QRRU轮数、混合精度 | 可能影响覆盖/精度，不属于首选；单独精度对照 |

H0继续用于支持区域和D2目标网格的粗残差先验；不会因速度优化把H0送进QRRU。分块改变不需要重新训练，但浮点计算路径可能不同，不能预先保证全量逐位一致。

证据：artifacts/semidense_chunk_benchmark_20260928.json；可复跑脚本 scripts/benchmark_semidense_chunks.py（拒绝覆盖已有结果）。数值排序补充核对使用 --verify-ordering。
