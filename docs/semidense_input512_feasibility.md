# 固定输入784→512：可行性讨论

分支：codex/semidense-input512-study，基于main的f38e0ec。当前E推理实际使用独立检出的正式半密集实现7cddb2a；本轮只审查代码、记录方案，没有改模型、搬入模型实现或启动训练。后续实施须以这份正式半密集代码为基线。

## 判断

工程难度中等，主要是全链路尺寸和坐标契约统一；不需要换骨干或设计新QRRU。保住原图像素精度比让模型运行更难。E权重的大部分结构具有动态空间尺寸、参数不依赖网格大小，适合直接加载后做512零微调对照；结构可加载不等于精度不变，尚未运行512。

代码依据：feature_provider固定输入Bx2x3x784x784和输出98/196/392；半密集infer及coarse_matcher固定98/392，QRRU边界391；计时、可视化、数据加载也有尺寸常量。LoMa提供的DINOv3 patch_size=16，extract_pair_descriptors按实际patch网格提取；MVT动态reshape/RoPE；Stage1HeadFromSharedMVT按实际height/width生成位置和拟合网格。旧LoRettaStage1H代码明确支持512→32×32和784→49×49，不需要人为插值token回49。

| 网格 | 784 | 512 |
|---|---|---|
| DINO/MVT/H0输入token网格 | 49×49 | 32×32 |
| D8 | 98×98 | 64×64 |
| D4 | 196×196 | 128×128 |
| D2 | 392×392 | 256×256 |

D8→D2比例仍为4，fine_grids的4×4子网格规则保持成立；QRRU的4×4采样窗口、2×2控制流和4轮递推可保持。H0残差先验继续只用于前面的粗/细路径，不向QRRU增加H0输入。

## 资源与速度

每层空间单元数比例为(512/784)^2≈42.65%，对应卷积空间计算/描述子存储理论减少57.35%。全量D8候选相似度元素9604²→4096²，约保留18.19%；DINO/MVT注意力的二次项也类似，但线性层、内存访问、调度等不按此比例下降，分块算法也并非驻留全量相似度矩阵。

不能承诺整机2.35倍或5.50倍提速。QRRU若仍输出最多12000点，其局部递推工作量可能接近原来，只有全图投影减少；fine实际候选数也由预测与上限共同决定。训练只采样1024个coarse正例/64个fine窗口/128个QRRU点，监督数量不随图面积同比减少。粗训练softmax分母变小，固定正例数的代价不能用全N²比例估算。

第一轮固定QRRU轮数、max_matches=12000、推理分块1024和训练分块32，避免把减少输出点数混作降分辨率收益。D8最多只有4096个源点，因此原max_coarse=6000自然不再可达。

## 精度及训练含义

以原图512×512为例，原来先放大到784：D2一个单位约对应512/392=1.306原图px；改为512后对应2px，原图覆盖扩大1.53125倍。D8间距约5.224→8原图px。P@1px更依赖稳定的亚像素细化；不意味着最终误差至少2px，QRRU仍能连续输出亚像素坐标。

细窗口与radius=1.5、noise_std=0.8、fine_gt_tolerance=1.5等以D2单位定义的量，在同一原图上的意义都会变化。784时fine容差约1.959原图px，512时约3px。零微调对照先保留原参数；适应训练时再单独比较“同D2单位”和“同原图覆盖”策略，不要混在第一轮里。512原生数据避免了先放大，但插值后的采样密度和网络感受野变化仍会影响已训练模型。

H0也从49×49上下文变为32×32，有限候选数量、softmax分布、matchability和拟合稳定性可能变化，必须单独统计H0失败率。现有MRSI已有31/600对invalid_h0；512能改善还是恶化不能预判。更低分辨率不会自动解决跨模态泛化。降低P@1的风险存在，但不是已证实结果。

GT坐标继续以原图定义，匹配坐标按实际D2大小和各原图尺寸还原：(u+0.5)*W/w_D2-0.5。输入和mask同步缩放，位置归一化与pixel-center约定保持一致，不能随意对H0矩阵乘512/784。指标1/3/5px始终是原图像素。当前条件RMSE还包含失败记10，比较分辨率时必须同时看SR和正确点数量。

## 建议执行顺序（尚未执行）

1. 将正式半密集代码纳入本实验分支，建立input_size配置（784默认、512可选）；共享编码、coarse匹配、fine、QRRU边界、数据/mask、可视化和计时统一由实际张量尺寸推导。避免简单全局替换常量影响历史784。
2. 做坐标闭环、GT监督、尺寸、E权重strict加载以及784回归检查；在512固定输入下验证完整前向和必要反向。首先不改权重。
3. 同一E权重比较784/512，在固定GoogleEarth验证集和expanded MRSI上按相同pair_id评分；控制输出预算，并记录H0失败、coarse/fine/final P@1/3/5、SR、当前条件RMSE、NCM、各模块时间与显存。先看512零微调的真实代价。
4. 若零微调损失可接受，或误差主要在下游，再以E初始化、低于原E峰值的学习率短程适应512；先冻结DINO/MVT/H0，仅训练VGG/CGMDP与下游。若H0失败明显增加，另立H0/MVT适应实验，不能指望只训练QRRU修复上游失败。新分辨率训练是新协议和新优化器，不能当作旧784精确resume。

建议保留784/512双配置，而非删除784基线。更改输入属于推理与训练分布的变化，区别于此前仅调整分块的执行优化。
